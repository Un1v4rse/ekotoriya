1. Общие сведения и принятые решения
База проекта: существующий прототип — Flask-клон сайта ekotoriya.ru (32 страницы) с админ-панелью, конструктором блоков, онлайн-редактором страниц и модулями синхронизации WB/Ozon. Настоящее ТЗ — план доработки прототипа до промышленной версии.
Источник товаров
Только Wildberries, продавец 175521 (интеграция Ozon из прототипа удаляется)
Доступ к ЛК WB
Имеется — API-токен «Контент» и «Цены и скидки»
Заказы
Оформляются на сайте (корзина, оплата, доставка, чеки 54-ФЗ)
Копия ekotoriya.ru
Полная — уже реализована в прототипе (32 страницы, статика локально)
Нагрузка
Неизвестна — проектирование с запасом, обязательный нагрузочный тест
Язык
Только русский

2.2. Критические пробелы и риски (устранить в первую очередь)
Проблема
Требуемое решение
Хранение в JSON-файлах (content.json, customers.json, wb_products.json) — нет БД: гонки при одновременной записи, нет транзакций, не масштабируется
Переход на PostgreSQL (SQLAlchemy + Alembic-миграции); JSON-файлы — только как экспорт/бэкап
Скидка админа НЕ отправляется в WB — меняется только локальная цена на сайте (set_admin_discount правит JSON). ТЗ требует проставления скидки через WB API
Интеграция с WB «Цены и скидки»: метод обновления скидки (goods-discount / API калькулятора скидок), расписание, откат, журнал
Нет корзины и онлайн-оплаты: «Купить в 1 клик» создаёт лишь заявку (имя/телефон). Нет платёжного шлюза, чеков 54-ФЗ, доставки, личного кабинета (заглушки /basket/, /personal/)
Полноценная корзина + оформление заказа: ЮKassa/CloudPayments, облачная касса, СДЭК/Boxberry, ЛК покупателя, статусы и уведомления
Рекомендации — глобальный топ по заказам+лайкам, без персонализации по клиенту и без событий просмотров
Событийная аналитика (просмотры/лайки/корзина/заказы) + персональные рекомендации: «с этим покупают», похожие, избранное со скидкой
Безопасность: логин/пароль admin/admin по умолчанию, HTTP Basic Auth, SECRET_KEY захардкожен, debug=True, нет CSRF, нет rate-limit, нет ролей
Сессионная авторизация админки, принудительная смена пароля, 2FA, CSRF-токены, rate-limit, роли (суперадмин/менеджер/контент/SEO), секреты в env
Производительность: make_context() на КАЖДЫЙ запрос читает content.json + wb_products.json + ozon_products.json + customers.json и пересчитывает популярное; рендер Jinja без кэша страниц
Кэш (Redis): готовые страницы, контекст, популярное; фоновые джобы синхронизации; Nginx + gunicorn
Нет автосинхронизации по расписанию (только кнопка в админке), нет логов синхронизации
Celery/RQ + Redis: расписание, ретраи, журнал с ошибками, уведомления админу
Нет резервирования остатков WB при заказе; нет учёта размеров/остатков в карточке (только первая цена из sizes[0])
Выгрузка остатков (складские остатки WB API), выбор размера, резерв/списание по настройке
Каталог: карточки товаров прототипа — демо-заглушки; нет фильтров, поиска, ЧПУ-каталога товаров (только /catalog/wb/&lt;nm_id&gt;/)
Полноценный каталог: фильтры (цена, размер, тип), поиск (Meilisearch), SEO-URL товаров и категорий
Ozon-модуль (ozon_sync.py) — по решению заказчика не требуется
Удалить модуль, эндпоинты /api/ozon-*, демо-товары и упоминания в админке/шаблонах
3. Функциональные требования (итоговая версия)
3.1. Каталог и интеграция Wildberries
Выгрузка карточек продавца 175521: Content API v2 (курсорная пагинация — готово в прототипе) + цены/скидки + складские остатки (добавить).
Синхронизация по расписанию (настраивается): каталог — 1 раз в N часов, цены/остатки — каждые 15–30 мин; журнал ошибок, ретраи, уведомление админу.
Скидка через WB API: при сохранении скидки в админке она отправляется в WB «Цены и скидки» (основной режим) либо применяется только на сайте (переключатель); распродажи с датами и авто-откатом; массовое применение по категории/выборке.
Карточка товара: фото-галерея, цена со скидкой, размеры с остатками, характеристики, рейтинг WB, хлебные крошки, «похожие товары», SEO-URL.
Каталог: категории (синхронизация с категориями WB), фильтры (цена, размер, назначение), поиск, сортировки (популярность, цена, новизна).
3.2. Корзина и оформление заказов
Корзина (вместо заглушки /basket/): позиции с размерами, количество, промокоды, сохранение для гостя и авторизованного.
Оформление: доставка (СДЭК/Boxberry/Почта — тарифы в админке), оплата (ЮKassa/CloudPayments, карты/СБП), чеки 54-ФЗ через облачную кассу.
Личный кабинет (вместо заглушек /personal/): заказы, избранное, повтор заказа, адреса, данные.
Статусы заказов и уведомления: email/SMS/Telegram (каналы в админке), трек-номер.
Списание остатков: со склада сайта + опциональный резерв/списание на WB через API.
3.3. Клиентская база и рекомендации
Автонаполнение базы при регистрации/заказе (логика готова) — перенос в PostgreSQL; сегментация RFM, экспорт.
Событийная аналитика: просмотры, лайки, корзина, заказы — таблица events.
Рекомендации: «с этим покупают» (совместные покупки), похожие товары, избранное со скидкой, персональный топ; глобальный топ по заказам+лайкам (готов) — для гостей и холодных клиентов.
Управление в админке: пин товаров, вкл/выкл блоков, метрики кликабельности.
3.4. Админ-панель и конструктор (на базе готового)
Сохранить и развить: онлайн-редактор на странице, конструктор блоков, WYSIWYG-предпросмотр, добавление/удаление страниц, загрузка файлов, пересборка шаблонов.
Добавить блоки: «Отзывы», «Форма обратной связи», «Карта», «FAQ/аккордеон», «Баннер/акция», «HTML» (есть).
Тема оформления: расширить до полного набора (палитра HEX по элементам, два шрифта + загрузка WOFF, скругления, отступы, стили карточек, анимации) с предпросмотром.
Разделы админки: товары (скидки, пины), заказы, клиенты, рассылки, синхронизации WB (логи, расписание), SEO, интеграции, роли пользователей.
Безопасность админки: сессии, смена пароля при первом входе, 2FA, роли, CSRF, audit-log действий.
3.5. SEO-модуль
Сохранить: title/h1/description на страницу (готово), robots.txt из админки (готово), sitemap.xml (готово), Яндекс.Метрика (готово).
Добавить: SEO-шаблоны с переменными для карточек товаров, 301-редиректы, Schema.org (Product, Breadcrumbs, Organization), Open Graph.
3.6. Производительность
Core Web Vitals: LCP &lt; 2,0 с, INP &lt; 200 мс, CLS &lt; 0,1; TTFB &lt; 300 мс.
Кэширование: Redis-кэш готовых страниц и контекста (устранить пересчёт на каждый запрос), CDN для статики, immutable-кэш (готово).
Изображения: WebP/AVIF-конвертация в прокси (готов прокси — добавить ресайз srcset).
Фоновые задачи: синхронизации, рекомендации, рассылки — в очереди (Celery/RQ).
Нагрузочный тест: 500+ одновременных пользователей, p95 &lt; 500 мс; горизонтальное масштабирование.

5. Этапы работ
Этап 0 (1 нед.): инфраструктура — PostgreSQL, Redis, Docker, миграции данных из JSON, вывод debug-режима, безопасность админки (сессии, пароли, роли).
Этап 1 (2 нед.): WB — остатки, автосинхронизация по расписанию, push скидок в WB API, журналы; удаление Ozon.
Этап 2 (2–3 нед.): корзина, оформление заказа, платёжный шлюз, чеки 54-ФЗ, доставка, личный кабинет, уведомления.
Этап 3 (1–2 нед.): событийная аналитика, персональные рекомендации, блоки на главной и в карточках.
Этап 4 (1–2 нед.): новые блоки конструктора, расширение темы оформления, SEO-модуль (шаблоны, редиректы, Schema.org).
Этап 5 (1 нед.): кэширование страниц, WebP-ресайз, нагрузочное тестирование, приёмка, запуск.

Доступ к хостингу и домену; подтверждение прав на контент клона либо заменяющие материалы.
Реквизиты для чеков и тексты юридических страниц (оферта, политика ПДн).
